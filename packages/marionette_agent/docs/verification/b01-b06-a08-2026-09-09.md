## A08

37回のCLI呼出しがすべて期待結果に一致し、runnerがPASSで完了した。

| 操作 | 期待結果 | 実結果 |
| --- | --- | --- |
| alpha/beta connect、alpha URIへの別名connect | 2sessionを保持、所有権競合を拒否 | 一覧2件、競合exit 3 |
| alphaのrefをbetaのtapに使用 | 別session ref拒否 | exit 4 |
| alphaでPageView refのleft 300、旧ref再使用 | Page 2、旧ref拒否 | Current page: 2、exit 4 |
| alphaで座標(100,556)→(350,556) | Page 1 | Current page: 1 |
| alphaのdismissible left 200 | Item dismissed | snapshotとPNGで削除確認 |
| alphaの操作前に取得したbeta refでtap | beta ref保持、画面状態分離 | beta count 0→1、Page 1とdismissibleを保持 |
| alpha close中のbeta tap、alpha再connect | beta継続、alpha ref失効、アプリ状態保持 | beta 1→2、alpha旧ref exit 4、alpha count 0のまま |
| alphaのVM Service TCP接続を切断 | disconnectedとref失効 | state: disconnected、snapshotValid: false、tap exit 3 |
| 切断中のbeta tap | 他sessionへ影響なし | beta 2→3 |
| alphaの同じURIへ明示connect、snapshot、tap | 再接続して操作可能 | alpha 0→1 |
| betaへ2つのtapを並行送信 | 各1回実行 | beta 3→5 |

通信断はrunner内の透過TCP relayで、**実際に接続済みのVM Serviceソケットを破棄**して発生させた。Backendは実際のMarionetteBackend、アプリもSimulator内の実プロセスで、FakeBackendは使っていない。relayは同じ待受URIを維持するので、認証URIやアプリを変更せず明示connectで復旧を検証できる。自動操作再送は行っていない。

最初のrunnerは公開応答のstate欄をstatusと誤記して停止した。実応答は既にdisconnectedであり製品の不具合ではなかった。判定を修正し、両fixtureをhot restartして初期状態から37呼出しを再実行した。
